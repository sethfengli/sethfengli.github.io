# 分片翻译任务规范（子代理必读，与 TRANSLATION-BRIEF.md 同时读）

你是慧灯禅院网站的中→英翻译。**先读** `scripts/TRANSLATION-BRIEF.md`（雅信达标准、术语、结构要求），
再读本文的硬性交付格式。派发提示词只给「源文件 / 输出文件 / firstBlock / 块数 / 是否带 meta」四要素，
其余要求以本文为准。

## 硬性要求（违反即返工）

1. **结构 1:1**：`blocks` 与源**块数相同、顺序相同、每块 `t` 相同**。
2. **片段不增不减**：`p`/`quote` 的 `inline` 片段数逐块一致；`table` 的行数/单元格数/每格片段数一致。
   **空的或纯标点的片段必须保留为独立片段**，禁止合并或丢弃。
3. **只翻译文字**：`href` 原样复制，只译链接文字（`s`）。
4. **输出格式**：`{"firstBlock": <源里的值，照抄>, "blocks": [...]}`。
   若派发信息标注 `meta=yes`，另加顶层 `"title"`/`"excerpt"`（源里有 `zhAuthor` 才加 `"author"`；
   **没有 `zhAuthor` 就不要编造 `author`**）。标注 `meta=no` 时**不要**加这三个字段。
5. **字符规则（权威版，别再自行加码）**
   - **禁止**：任何 CJK 汉字；任何全角字符（【】〔〕《》（）「」、。，！？：；）。
   - **允许且推荐**（与同篇既有分片保持一致即可）：英文弯引号 “ ” ‘ ’、em dash `—`、
     间隔号 `·`(U+00B7)、省略号 `…`(U+2026)。
   - `《》` 一律去掉，书名用 Title Case。
6. **合法 JSON**：无注释、无尾逗号、无 BOM、**禁止** `<<<MORE>>>` 之类占位符；单文件，**不要拆成多个 part**。
7. **大小与分阶段写入**：成品可能 40–180KB。必须**分多次** `write`/`edit` 追加（每次 <40KB），
   且**每一步结束后文件都是合法 JSON**。
8. **不许碰其它文件**：只写指定的输出文件；不要跑 git 命令。

## 若上下文将尽（重要，允许的降级）

停止追加，保证文件仍是**合法 JSON 且包含你已完成的连续块**（顺序与 firstBlock 不变），
在报告里写清「已完成到第 N 块」。父代理会另派任务补完剩余区间 —— **绝不要**写占位符或截断 JSON。

## 质量

信（忠于经义与古德法语）· 达（地道流畅，无翻译腔）· 雅（偈颂译成有韵律的英文诗，尽量押韵）。
术语用通行梵/巴利/英译（bodhi, prajñā, samādhi, nirvāṇa, Pure Land, Amitābha Buddha, Chan/Zen, nianfo …）。
**与同篇既有分片保持一致**（用名、拼写、标点风格参照相邻分片）。

## 自检（必做）

写完运行（在仓库根目录）：
```
node scripts/verify-slices.mjs <你的输出文件名>
```
必须打印以 `ok` 或 `ok(big)` 开头的行。若报 `crit`，**修到 `ok` 再结束**。

## 报告（一段话）

状态 / 文件路径 / 写入块数 vs 要求块数 / `verify-slices` 输出行。
