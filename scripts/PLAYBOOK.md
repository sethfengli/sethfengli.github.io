## 3. 步骤削减措施（本会话 384 步 / 10 轮 ≈ 38 步/轮 → 目标 ≤12 步/轮）

按收益排序，**逐条执行**：

| # | 措施 | 省下的开销 |
| --- | --- | --- |
| 1 | **不要用 goal 工具**（本会话 20 个目标轮在子代理还在跑时被秒级触发，产生约 20 条空转消息）。长任务靠子代理完成通知驱动即可。 | ~20 消息/会话 |
| 2 | **通知轮一律 0 工具调用**：收到某个子代理的完成通知时，若本轮还有任务在飞，只回一行字，**不要** `list_agents`/`check-parts`/`coverage`。 | ~10–15 调用/轮 |
| 3 | **每轮只在「最后一个任务结束」后做一次批量收尾**：一条消息里跑 `verify-slices`（多片一次）→ `merge-parts`（多篇一次）→ `repair-json` → `validate-en` → 一次 commit。 | ~6–8 调用/轮 |
| 4 | **派发提示词模板化**：把全部硬性要求放进 `scripts/DISPATCH.md`，子代理提示词缩到 ~8 行（只给 `partName`/`firstBlock`/`blocks`/`meta`）。本会话每轮写 5 段长提示词（约 6k token/轮）。 | ~60–75% 输出 token |
| 5 | **一次规划整个任务队列**：`node scripts/task-plan.mjs 120 > build/queue.txt`，之后每轮从队列取前 N 个，不再每轮重跑 `coverage`/`pick-next` 分析。 | ~3–5 调用/轮 |
| 6 | **提高并行度到 8**（若允许）：5 轮替代 8 轮，直接砍掉 3 轮的全部固定开销。 | ~35% 总步骤 |
| 7 | **诊断/文档集中做**：本会话为「修正任务」产生约 15 个文档提交、约 20 条分析消息。改为**每 3–5 轮或会话末一次性写**（工具脚本除外，它们必须当场固化）。 | ~15–20 消息/会话 |
| 8 | **被乱码/CJK 挡住的 14 个任务单独成批**：集中一轮做「修复→合并」，不要混在正常轮里反复判定。 | 避免每轮重复过滤 |

## 4. 每轮标准操作（照抄，不必再思考）

```
# 0) 一次性：生成队列
node scripts/task-plan.mjs 120 > build/queue.txt

# 1) 取本轮 N 个任务（N=8 推荐），预提取源文
node scripts/gap-prep.mjs <slug>:<start>-<end> ...      # 队列里的每个任务
#    头片(从 0 开始)记得确认 meta；被 meta-scan 命中的篇先删 zhAuthor

# 2) 一条消息里并行派发 N 个子代理
#    提示词 = 「读 scripts/DISPATCH.md + scripts/TRANSLATION-BRIEF.md；
#            源 build/slices/<part>.src.json → 输出 src/content/en/<part>.json；
#            firstBlock=<n> blocks=<m> meta=<y/n>；自跑 verify-slices 到 ok」

# 3) 等通知：非最后一个通知 → 只回一行，0 工具调用

# 4) 最后一个通知到达后，一条消息内批量收尾
node scripts/verify-slices.mjs <part1> <part2> ...      # 一次核验本轮全部分片
node scripts/merge-parts.mjs <slug1> <slug2> ...        # 一次合并本轮齐了的篇
node scripts/repair-json.mjs && node scripts/validate-en.mjs
git add <slug>.json ...            # 先单独加合并产物
git add -u src/content/en -- ':!<仍在写的分片>'
git commit -m "EN: A round N - ..."
git show --stat --oneline HEAD     # 核对含新增整篇
```

## 5. 红旗（命中就立刻停下处理，别带着跑）

1. `validate-en` 的 **crit 数字上升** → 一定是合并把既有分片的隐性缺陷引爆了（本会话 095 的 `〔`）。
2. 某篇出现**同区间两个分片** → `merge-parts` 会 `[gap]/[fail]`；先删多余/嵌套孤儿。
3. 子代理报告 **mojibake / 双重编码** → 立刻 `node scripts/scan-mojibake.mjs` 复核（PowerShell 文本管道是元凶，禁止使用）。
4. `git commit` 后 `--stat` 里**没有新增整篇** → pathspec 失败的静默陷阱，`git add <slug>.json && git commit --amend`。
5. `meta-scan` 命中的篇**没处理就派发** → 子代理会把书名/章标题当作者写进整篇（`020` 已踩过）。
